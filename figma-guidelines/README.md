# Okko UI Type — пакет для Figma Design Agent

Обновлено 17 ноября 2026. Это отдельная адаптация правил Codex к библиотечным Guidelines Figma и одному запускаемому skill.

## Что загрузить

В каталоге ui-type находятся ровно шесть Guidelines:

| Файл | Назначение |
|---|---|
| overview.md | Назначение, разбор концепта, роль дизайнера и полный результат |
| tokens.md | Привязки, темы, интервалы, рекомендательный подбор радиуса |
| components.md | Источники компонентов, правило 15%, Custom, слоты и Heading |
| layouts.md | Структура, нейминг, Auto Layout, сетки и подписи breakpoint |
| platforms.md | Раздельная геометрия iOS, Android, Web и исключения |
| anti-patterns.md | Ошибочные решения, правильная альтернатива и причина |

Это предметные правила Rail, а не общий каталог всех компонентов Okko. TV и будущий Grid не имеют утверждённых правил сборки в этом пакете.

## Установка Guidelines

Guidelines — обычные Markdown-файлы без обязательного frontmatter; они привязываются к опубликованной библиотеке. Figma рекомендует 3–8 тематических файлов суммарно менее 100 KB, технический лимит — 200 KB. Источник: [Figma Help — Guidelines](https://help.figma.com/hc/en-us/articles/43509372175511-Add-guidelines-files-to-a-design-library).

1. Открой библиотеку [UI Type Web & Mobile](https://www.figma.com/design/TGfdPRzrhCA6CbiHsRjBSD).
2. Выбери Library → Manage guidelines → Upload.
3. Выбери шесть .md-файлов из ui-type и нажми Apply changes.

В диалоге Figma Agent подключи UI Type через Libraries. Для нужных базовых зависимостей подключи соответствующие Lib-iOS, Lib-Android-Mobile, Lib-Web и предусмотренные общие библиотеки. Правила Rail загружаются в библиотеку-владельца UI Type; общий пакет не нужно размножать по всем платформенным библиотекам.

Публикация UI Type в текущей работе не подтверждена. Если библиотека ещё не опубликована или недоступна в Libraries, дизайнеру нужно решить этот вопрос перед проверкой сценария с библиотечным контекстом. Подготовка файлов не публикует библиотеку.

Загружай файлы ui-type, а не этот README, старые полные инструкции или архив целиком. При обновлении замени соответствующий файл через Replace; держи один действующий комплект без дублирующих версий.

## Запускаемая команда

Файл skills/ui-type-rail-build.md — отдельный skill с YAML name/description и workflow. Загрузка skill: в чате Skills → Add skill → Upload a file, выбрать этот .md, проверить содержимое и нажать Add. Запуск: /ui-type-rail-build. Figma принимает skill одним Markdown-файлом, без дополнительных каталогов references/scripts/assets. Источник: [Figma Help — custom skills](https://help.figma.com/hc/en-us/articles/40283639496599-Create-and-manage-custom-skills-in-Figma).

Guidelines задают правила библиотеки; skill организует выполнение и содержит резервную копию правил на случай, если Guidelines не доступны агенту. При работе внутри самой UI Type он сначала ищет локальные мастера, не требует подключения этого же файла как внешней библиотеки и принимает указанную дизайнером рабочую ветку. Внешнее подключение нужно только для отсутствующих зависимостей. Файлы Codex автоматически в Figma не переносятся.

Пример запроса после установки:

```text
/ui-type-rail-build
По приложенному концепту собери Rail <имя> для iOS, Android и Web.
Используй UI Type и подключённые платформенные библиотеки.
Собери полное покрытие 5/3/6 на отдельной тестовой странице.
Сохрани явные настройки концепта; допущения перечисли.
Передай ссылки на три набора и результат проверки.
```

## Статус и проверка

Пакет проверяется локально по UTF-8, структуре, ссылкам, размеру и содержимому архива; импорт и поведение Figma Agent ещё не проверены. Обновлённый пакет ещё не проверен повторным запуском Figma Agent. Подготовленные в библиотеке секции проверки не доказывают применение новой версии Guidelines самим Figma Agent.

Критерии теста: дефолтная картинка-плейсхолдер на всех обложках; проверочные секции на устройствах с видимыми локальными сетками; ошибки показаны без автоматической правки; Carousel без clipping; внутренние экземпляры не экспонированы без запроса; все запчасти с x / и Slot для наполнения слотов; сохранён смысл концепта; реально собраны 5 iOS/3 Android/6 Web; карточки, Heading и базы связаны с нужными мастерами; восстановлены семь boolean-связей, сохранены скрытые элементы; новые Overlay/Caption — FRAME, исходные SLOT сохраняются только при точном переносе; пропорции выбраны по правилу 15%; радиусы остаются переменными; дизайнерская донастройка не сброшена; фактические размеры и ограничения переданы. Проверка только внешнего вида не заменяет проверку зависимостей.

Открытые вопросы сохранены в файлах: точные внутренние Rail Card Padding Gap; поведение между опорными Web-размерами; проверка рекомендательной шкалы радиусов. Имена неподтверждённых токенов не придуманы.

## Поддержка

Исходные подробные правила — .agents/skills/build-ui-type/references и .agents/skills/rail-layout-guides/references. Этот комплект отредактирован специально для Figma: без локальных путей, вызовов MCP, сырых аудитов и длинного списка nodeId. После изменения правил обновляй оба представления.

Предыдущие файлы figma-agent-skills/ui-type-builder.md и rail-layout-guides.md содержат полные экспорты правил Codex для отдельного использования; для сценария с библиотечными Guidelines используй новый каталог figma-guidelines. Архив нового пакета — dist/okko-ui-type-figma-guidelines.zip. Для обновления полных экспортов отдельно запусти python3 scripts/export-ui-type-figma-skills.py.

Для обновления резервного справочника внутри skill и архива запусти python scripts/package-figma-guidelines.py. Справочник собирается из шести актуальных файлов ui-type, чтобы не поддерживать отдельные расходящиеся копии.

Подход с правилами и примерами также описан в [официальной статье Figma](https://www.figma.com/blog/how-to-put-your-design-system-to-work-with-the-figma-agent/).

## Актуальные уточнения

Android: gutter сетки и межкарточный gap используют одни Rail Gap 6/8. Все запчасти публикуются в группе x / . Базовые Card, Heading, Rail Example, общие запчасти и сетки находятся на Rail Shared; экземпляр Rail Example можно detach с сохранением связей вложенных баз. При сборке по концепту все обложки получают библиотечный дефолтный плейсхолдер. Проверка выполняется на устройствах с локальными guides; ошибки не исправляются автоматически.

## Сценарий продуктового дизайнера

Подключить опубликованную UI Type в фича-файле → собрать Rail рядом с концептом → доработать локальный компонент → согласовать → перенести в UI Type → адаптировать остальные платформы → опубликовать по явному запросу.

Пример запроса с библиотечными Guidelines, без установки отдельного skill:

```text
По этому концепту собери Rail Media для Web в текущем фича-файле.
Используй подключённую UI Type и её Guidelines, связанные Card и Heading.
Создай локальный компонент и проверку на шести Web-брейкпойнтах.
```

Skill /ui-type-rail-build — дополнительная запускаемая команда. Подключение библиотеки передаёт Guidelines, но не считается автоматической установкой пользовательского skill. Его установка описана выше. В будущем Rail и Grid получают отдельные команды, общий пакет Guidelines остаётся у библиотеки UI Type.

## Собственная карточка UI Type

Редакция 18 ноября: рабочая карточка — самостоятельный мастер по размерам, Rail Card — шаблон; новые слоты не добавляются, семь переключателей восстанавливаются. Подробная схема, алгоритм detach, таблица свойств, сохранение overrides и тесты находятся в ui-type/components.md и включаются в резервный справочник skill. Контроль установки: новая команда должна создать собственный набор карточек и проверить два ресайза мастера, а не оставить прямые Rail Card в Carousel. Подготовка пакета не означает, что установленная в Figma версия уже заменена.
