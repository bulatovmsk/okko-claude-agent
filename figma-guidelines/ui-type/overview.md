# Okko UI Type — назначение и сборка по концепту

Эти Guidelines относятся к библиотеке UI Type Web & Mobile:
https://www.figma.com/design/TGfdPRzrhCA6CbiHsRjBSD
Они описывают Rail для iOS, Android Mobile и Web с Desktop. Grid и TV требуют отдельных подтверждённых правил: текущие Rail-формулы к ним автоматически не применяются.

## Роль инструмента

Создай полноценную редактируемую компонентную основу по концепту продуктового дизайнера. Концепт может быть текстом, вайрфреймом из прямоугольников, изображением или подробным дизайном. Дизайнер оценивает результат, донастраивает его и принимает окончательное решение.

Низкая детализация концепта не требует рисовать компоненты с нуля. Выбери существующие компоненты и платформенные стили. Не добавляй неуказанные действия и контентные поля ради декоративной полноты.

При пересборке сохраняй явные дизайнерские настройки. Отличие от рекомендательной шкалы радиусов не является ошибкой. Не сбрасывай донастройку к исходной рекомендации.

## Решения до сборки

Сначала проверь компоненты на доступных страницах текущего файла. Если локальные мастера Rail Card и Rail Heading уже здесь, используй их напрямую; подключать тот же файл как внешнюю библиотеку не требуется для поиска этих мастеров. Проверяй реальные узлы и связи, не одно название файла. Ветка или копия с другим file key допустима, когда дизайнер задал её как рабочую и нужные мастера доступны. Внешнее подключение запрашивается только для отсутствующей зависимости.

Определи назначение Rail, повторяемую единицу (карточка или многорядная колонка), контент, действия, подписи, ряды, пропорции и состояния. Отличай заданное дизайнером от унаследованного библиотечного правила и собственного допущения.

Составь соответствие: элемент концепта → реальный мастер → платформа → слот/свойство → источник размера. Для нового типа используй ближайшее проверенное семейство как источник геометрии только при совпадении композиции. Укажи, какие параметры наследуются.

Неизвестные N, span или размер нового iOS-типа не выдавай за утверждённые. Если несколько трактовок меняют смысл или композицию, уточни выбор; независимую понятную часть продолжай. Не требуй подробного макета только ради наличия всех пиксельных значений.

## Охват по умолчанию

Общий запрос «собери UI Type» означает три платформенных набора и 14 геометрических вариантов: 5 iOS, 3 Android, 6 Web. Подробные размеры — в platforms.md. Явный поднабор пользователя имеет приоритет. Один мобильный концепт сам по себе не ограничивает результат мобильной платформой.

Полная сборка — законченная основа на всех запрошенных размерах со связями, содержимым слотов и проверкой. Последующая работа дизайнера не оправдывает пропущенные платформы.

## Передача

Дай ссылки на три набора или запрошенный поднабор, перечень размеров, источники геометрии, ссылки на проверочные секции на устройствах с включёнными локальными сетками, результат структурной и визуальной проверки, существенные допущения и ограничения. Успешное создание узлов не означает дизайнерского утверждения. Найденные при проверке ошибки не исправляй автоматически: покажи результат дизайнеру с ожидаемыми и фактическими значениями.

Токены описаны в tokens.md, выбор компонентов — в components.md, структура и сетки — в layouts.md, платформенная геометрия — в platforms.md, типичные ошибочные решения — в anti-patterns.md. Все шесть файлов относятся к одному комплекту.
