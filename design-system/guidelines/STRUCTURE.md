# Структура гайдлайна компонента ДС Окко

Документ описывает **унифицированную структуру** документации компонента в Figma-библиотеке. На основе анализа эталонов:

- Button — `node-id=31214-29705`
- BottomSheet — `node-id=28934-239837`
- TabGroup — `node-id=24233-7754`
- **Chips — `node-id=39348-13491`** (`Component guide_Chips`, наиболее свежий эталон)

Файл: `Lib-iOS` (fileKey `rMcDm5qGp4CXkXXddEbcMh`).

> **Дополнительные типы секций, выявленные на эталоне Chips** (не входили в исходный список 1–15):
> - **Состояние выбора** (`23`) — отдельно от Состояний; про toggle Selected
> - **Область нажатия** (`24`) — hit-area, «реагирует по всей площади»
> - **Компонентные токены** (`22`) — группа (Control), компонентные токены, переключение по девайсам через моды
> - **Настройки компонента** (`3`) у Chips — это про *где найти* свойства (правая панель + DevMode Playground), а не таблица свойств
> - **Стили** (`6`) у Chips = размерные варианты (стандартный/малый), не Type

## Общий каркас фрейма гайдлайна

| Параметр | Значение |
|---|---|
| Ширина внешнего фрейма | **2776px** (контент 2376px + padding 200×200) |
| Высота | Зависит от компонента (8000–18000px) |
| Тёма | Тёмная (фон тёмно-серый, текст белый) |
| Имя фрейма | `Component guide` или `Component guide_<Name>` |

В библиотеке существует набор переиспользуемых инстансов для оформления:

- **`Title`** — заголовок секции
- **`Status bar`** — статус-бар iOS (декоративный, для визуального контекста)
- **`Pointer`** — стрелка-аннотация (для анатомии)
- **`Cursor`** — указатель курсора (для иллюстрации интерактивности в таблице состояний)
- **Decorative frames** — стандартные размеры для иллюстраций: `375×667` (iPhone SE), `390×720` (iPhone), `768×1024` (iPad)

## Секции гайдлайна (по порядку сверху вниз)

Все секции делятся на **обязательные**, **рекомендованные** и **компонент-специфичные**.
Skill `okko-doc-writer` должен генерировать как минимум все обязательные.

### 1. Шапка ⭐ обязательно

- Большой заголовок: имя компонента
- Подзаголовок 1–2 строки: что это и зачем
- Список 3–5 ключевых принципов / возможностей (буллет-листом)
- Якорь-чипы: пилюли-ссылки на основные секции для быстрой навигации

См. [`section-templates/01-header.md`](section-templates/01-header.md).

### 2. Когда использовать ⭐ обязательно

- 2–4 буллета: типичные сценарии
- 2–3 иллюстрации в контексте: реальные экраны Окко с компонентом

См. [`section-templates/02-when-to-use.md`](section-templates/02-when-to-use.md).

### 3. Когда НЕ использовать ⭐ обязательно

- 2–4 буллета: контр-сценарии
- Для каждого — указание, какой компонент использовать **вместо**

См. [`section-templates/03-when-not-to-use.md`](section-templates/03-when-not-to-use.md).

### 4. Анатомия компонента ⭐ обязательно

- Изолированная иллюстрация компонента
- `Pointer`-стрелки с подписями для каждой части: что это, какие свойства определяют

См. [`section-templates/04-anatomy.md`](section-templates/04-anatomy.md).

### 5. Настройки компонента ⭐ обязательно

- Скриншот панели свойств из Figma (Properties panel)
- `Pointer`-аннотации: что меняет каждое свойство

См. [`section-templates/05-properties.md`](section-templates/05-properties.md).

### 6. Варианты / Тип 🔵 рекомендовано

- Все Variant-варианты компонента (Primary / Secondary / Ghost и т.п.)
- Колонками: пример + название + назначение

См. [`section-templates/06-variants.md`](section-templates/06-variants.md).

### 7. Размеры 🔵 рекомендовано

- Все Size-варианты (Default / Small / Large)
- Сравнительная таблица с подписями

См. [`section-templates/07-sizes.md`](section-templates/07-sizes.md).

### 8. Состояния ⭐ обязательно (если компонент интерактивный)

- Таблица состояний (обычно: `Rest` / `Touch` / `Disabled` / `Loading` / `Progress`)
- `Cursor` для индикации состояния
- Колонки = состояния, строки = вариации/размеры

См. [`section-templates/08-states.md`](section-templates/08-states.md).

### 9. Иконка 🔵 рекомендовано (если компонент поддерживает иконку)

- Варианты с/без иконки, слева/справа
- Размер и отступы иконки

См. [`section-templates/09-icon.md`](section-templates/09-icon.md).

### 10. Отступы 🔵 рекомендовано

- Внутренние отступы (padding)
- Платформенные различия (iPhone / iPad / Web / TV)
- Иллюстрация с размерами

См. [`section-templates/10-spacing.md`](section-templates/10-spacing.md).

### 11. Текст 🔵 рекомендовано (если компонент текстовый)

- Длина: min / max символов
- Поведение при переполнении (truncate, wrap, multi-line)
- Регистр (если важен)

См. [`section-templates/11-text.md`](section-templates/11-text.md).

### 12. Как использовать (Do / Don't) ⭐ обязательно

- Пары «правильно» / «неправильно» в зелёной / красной рамке
- Краткая подпись: что именно не так в don't-варианте

См. [`section-templates/12-do-dont.md`](section-templates/12-do-dont.md).

### 13. Компонент-специфичные секции ⚪ опционально

Для компонентов с уникальными свойствами добавляются дополнительные секции. Примеры:

- **BottomSheet:** Detent, Maximum height, Swipe area, Content rules
- **TabGroup:** Tab types, Tab width, Tab arrangement
- **Button:** (всё стандартное покрыто 1–12)

Skill должен задать вопрос: «есть ли уникальные свойства компонента, которым нужны отдельные секции?».

### 14. Применение в полном экране ⭐ обязательно

- 1–2 финальных полноэкранных скриншота с компонентом в реальном контексте
- Платформа iPhone (390×720) или iPad (768×1024)

См. [`section-templates/14-fullscreen-application.md`](section-templates/14-fullscreen-application.md).

### 15. Связанные компоненты 🔵 рекомендовано

- Список компонентов, на которые ссылается / с которыми взаимодействует
- Краткое описание разницы

См. [`section-templates/15-related.md`](section-templates/15-related.md).

## Правила тонкой настройки

1. **Порядок секций фиксирован.** Если секция отсутствует — пропускается, но порядок остальных не меняется.
2. **Без пустых секций.** Если по компоненту нет данных для секции (например, нет иконки) — секция не создаётся вовсе.
3. **Текст на русском.** Технические термины (variant, state, padding) — на русском с пояснением в скобках при первом употреблении.
4. **Иллюстрации > слов.** Любую секцию о применении сопровождаем визуальным примером.
5. **Каждая аннотация — на токен.** В подписях `Pointer` указываем не magic-значения («16px»), а токены (`spacing.button.h`).

## Что должен уметь Skill `okko-doc-writer`

1. Получить из Figma:
   - Целевой компонент (его variants, properties)
   - Существующие шаблонные секции (фреймы с именами `1`, `2`, ..., `21`)
   - Инстансы `Title`, `Pointer`, `Cursor` для оформления
2. Построить список секций для конкретного компонента (отметить обязательные/рекомендованные/опциональные).
3. Спросить у дизайнера про компонент-специфичные секции, если они нужны.
4. Сгенерировать драфт гайдлайна:
   - Поднять или скопировать шаблонные фреймы
   - Заполнить тексты (заголовки, описания, подписи)
   - Расставить иллюстрации компонента и его вариантов
5. Положить готовый драфт в нужное место Figma-файла (через `use_figma` MCP).
6. Уведомить дизайнера, какие места требуют ручной проверки (иллюстрации в контексте, тексты Do/Don't).
