# Контекст UI Type Rail

Состояние на 17 ноября 2026. Точка продолжения на рабочем MacBook.

## Цель и инструменты

По концепту дизайнера любой детализации собирать полноценную компонентную основу Rail для iOS, Android и Web; дизайнер затем донастраивает результат.

- Codex: $build-ui-type — все платформы или выбранный поднабор; $rail-layout-guides — сетки. Отдельный iOS-скилл удалён.
- Figma Agent: /ui-type-rail-build. Шесть Guidelines и файл команды находятся в figma-guidelines/; инструкция загрузки — в README этой папки.
- Подробные правила и карта мастеров уже сохранены в .agents/skills/build-ui-type/references/. Перечитывать старую переписку для новой сборки не требуется.

Основная библиотека: https://www.figma.com/design/TGfdPRzrhCA6CbiHsRjBSD

## Ключевые решения

При сборке UI Type по концепту на все обложки всегда ставится существующая дефолтная картинка-плейсхолдер библиотеки, на всех платформах. Серые заливки и контентные изображения концепта её не заменяют. Правило не означает автоматическую замену изображений в существующих Rail при проверке.

Карточки и общий Heading берутся из UI Type, базовые компоненты — из платформенных библиотек. Совместимые запчасти переиспользуются. Мастера iOS → Android → Web стоят в ряд без секций-обёрток.

Отклонение пропорции до 15% включительно — ближайшая подходящая фиксированная пропорция; больше — Custom. Радиус выбирается по минимальной стороне через существующий токен Rail Card; шкала рекомендательная. Явные настройки дизайнера сохраняются. iOS использует утверждённые фиксированные размеры, Android — сетку, Web — свою формулу. Новые переменные и токены создавать запрещено.

## Организация и проверка библиотеки

Базовые Rail Card, Heading, Rail Example, общие запчасти и сетки объединены на Rail Shared (0:1); прежняя страница Rail Card удалена. Rail Example — пример композиции, его экземпляр разрешено detach с сохранением связей вложенных баз. Все 37 запчастей, включая общие, имеют префикс x / и остаются публикуемыми; скрывающий _ не применяется. Для новых компонентов наполнения слотов в имени сохраняется Slot.

Проверка организуется отдельными секциями iOS, Android M и Web на полноразмерных экранах с локальными сетками. Общий Preview не создаётся. Carousel имеет clipsContent=false; переполнение ограничивает экранный фрейм. Внутренние экземпляры не экспонируются в конечном Rail без явного запроса. Во время проверки ошибки показываются дизайнеру без автоматических исправлений; N не подгоняется обратной формулой под ширину концепта.

В библиотеке 16 ноября подготовлены 57 секций проверки для 19 типов: 205 связанных вариантов и 61 явная пометка о недостающем варианте, всего 266 экранов. Семь старых Preview удалены. Мастера не исправлялись, отображение guides в UI не подтверждено. Темы и прототипы всех вариантов полностью не проверены.

## Фича-файл как рабочая область

Новый сценарий — сборка локального Rail в фича-файле из опубликованных связанных баз UI Type, дизайнерская доработка, затем явный перенос согласованного компонента и запчастей в библиотеку с адаптацией остальных платформ. Правила синхронизированы в Codex и figma-guidelines. Публикация и загрузка обновлённого пакета в Figma ещё не подтверждены.

## Принятая собственная карточка UI Type — 18 ноября

На Continue проверена и принята новая архитектура: Rail Card — шаблон; detach только внешнего экземпляра → самостоятельный x / Rail <тип> Card iOS/Android/Web → связанные экземпляры в карусели. В новой карточке Overlay/Caption — FRAME без SLOT. Обязательны семь рабочих boolean-свойств: Small/Large/Indicator/Rich label, Skeleton, Card caption, Cover elements. Размеры/структура наследуются от мастера, root width/height overrides не должны блокировать правки. Служебное «Смотреть всё» остаётся отдельно. Точные переносы существующих компонентов с настоящими слотами (Featured Meta) сохраняют их слоты и изображения. Подробности — references/card-component.md. Остальные существующие типы автоматически не мигрировать.


## После слияния ветки «Правки»

Актуальный файл для дальнейшей работы — основная библиотека `TGfdPRzrhCA6CbiHsRjBSD`. Страницы называй `<тип> Rail`, например `Vertical Rail`. Сортируй их по названию типа внутри существующих групп и сохраняй разделители. Для Grid используется формат `<тип> Grid`. Эмодзи ставь только в именах основных платформенных UI Type, включая Grid, Featured и Banner. Имена страниц, базовых компонентов и запчастей сохраняй без платформенных эмодзи. Основные компоненты `Rail <тип> 🍎 iOS`, `Rail <тип> 🤖 Android`, `Rail <тип> 🌐 Web`.

[Android Grid в базе знаний](../design-system/components/grid-android-ui-type.md) — восемь наборов после слияния, размеры, число колонок, зазоры и правила ресайза.

Square Small 1 Story и 2 Story используют общие наборы `x / Rail Square Small Card` по платформам. Мастера находятся на Square Small 2 Story Rail. На Web сохрани варианты `Layout` внутри общего набора, включая вариант с подписью. Для проверки 1 Story ищи мастер по связи экземпляра, даже если он на другой странице.

Скелетон: непрозрачная подложка `color/fill/technical/placeholder` под градиентом `color/fill/technical/skeleton`, общий переключатель видимости. При проверке Rail Heading переключи `Show arrow` на связанном экземпляре на ширине целевого устройства. Заголовок остаётся у левого края в обоих состояниях, видимая стрелка Base Phone/Tablet — у правого. В Base Tablet используй `Content = Fill container` и `Title = Hug contents`: при скрытой стрелке контейнер с `Space between` и `Content = Hug contents` центрирует заголовок. Актуальные ID Featured, Banner, Grid и Continue — в references/current-library.md.

Внутренние padding и gap карточек при сборке и пересборке привязывай к семантическим `spacing/*` из Tokens Web&Mobile. Исторические примеры со значениями без привязки или с токеном радиуса внутри карточки это правило не задают.
