## Что зафиксировано

Карточки iOS, Android и Web перенесены в UI Type. Внутри них базовые Label, Rich Label, кнопки и прочие элементы сохраняют зависимости платформенных библиотек. Rail Heading общий, Desktop уже добавлен. Уникальные детали хранятся рядом с типом; совместимые существующие детали переиспользуются.

Компоненты именуются Rail Main iOS / Rail Main Android / Rail Main Web и аналогично для остальных типов. Они стоят в ряд iOS → Android → Web. Мастера не оборачиваются секциями, общие детали не дублируются. Удалённый пользователем Rail Ticket не восстанавливается.

Добавлен Shape=Custom с двумя настоящими слотами. Теперь допустимы стандартная Rail Card, Rail Card Custom и полностью кастомная карточка. Старая причина пропуска UI Type из-за нестандартных пропорций отменена; это не доказывает готовность всех ранее отложенных типов.

Для радиусов карточки используются исключительно переменные rail/card/radius/* с поддержкой темы. Gap карусели — rail/gap-horizontal/*. Точное семейство внутренних Rail Card Padding Gap пока не подтверждено; не выдавать жёстко заданные 6/2 за связанные токены.

## Геометрия по платформам

- iOS: 5 утверждённых устройств. Сохраняются фиксированные размеры карточек, Technical JSON — проверка. iPhone Main 226 px рассчитывался по базе 390 px, хотя текущий шаблон 393 px. Автоматически менять на 228 нельзя. Промежутки K=max(0,ceil(N)−1).
- Android: Phone 360, Tablet Portrait 640, Tablet Landscape 1024. Сетка 8 колонок/gutter 8 и 12/gutter 12, padding 16/24. Специальный R не вводится. Gap карусели 6/8 отличается от gutter.
- Web: breakpoint 320, 375, 768, 1024, 1440, 1920. Формула W=(S−L−R−((N−1)×G))/N. R=36/36/56/56/56/72; padding=12/12/32/32/56/72; gap=6/6/8/8/8/10. На 1440 Device Desktop использует gap tablet. R реконструирован по геометрии, Web Technical-токен не найден. Highlights/Announces требуют собственной проверки.

N задаётся для конкретного типа и размера; число экземпляров в карусели его не определяет. Подробности и исключения находятся в платформенных references навыка.

## На чём остановились

Последним завершённым действием добавлены Web-подписи breakpoint к [Layout Guides](https://www.figma.com/design/TGfdPRzrhCA6CbiHsRjBSD?node-id=125-21651) и значения breakpoint в названия нативных стилей:
- Web/Mobile (320, 375);
- Web/Tablet (768, 1024);
- Web/Desktop M (1440);
- Web/Desktop L (1920).

Android/Phone и Android/Tablet сделаны ранее. Всего 6 новых стилей и 10 примеров. 440 — только пример растяжения Mobile. Существующие iOS guides сохранены. Проверены размеры, привязки и растяжение; обычный экспорт Figma не показывает нативные сетки.

Дальнейшая содержательная работа — проверять каждый Rail с дизайнером и исправлять конкретные замечания по актуальным правилам. Полная инвентаризация всех скрытых состояний всей библиотеки не объявляется завершённой только на основании прежнего аудита нейминга.

## Что остаётся открытым

Точное имя и назначение переменных внутренних padding/gap Rail Card; хранение R и N Web в Technical; поведение конкретных Web-типов между опорными брейкпойнтами; подтверждение публикации библиотеки. Новые переменные в проекте создавать запрещено, существующие импортировать можно.

Расчёт Materials/Vemo по отдельному запросу в Lib-Web был отдельной задачей и не определяет место остановки работы над UI Type. Исторические отчёты о пропусках типов и старый навык только для iOS не должны отменять последние решения.
