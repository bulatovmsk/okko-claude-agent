# Skill: Overview вариантов компонента

## Когда применять

Используй для variant matrix, regression board и проверки покрытия component set. Это тестовый стенд, а не пользовательский гайд.

## Источник комбинаций

- Читай variants и component properties непосредственно из целевого `COMPONENT_SET`.
- Используй только реально существующие комбинации. Не создавай декартово произведение значений, которого нет в component set.
- До построения посчитай уникальные комбинации, дубли и пропуски.
- Если на странице несколько публичных component sets, делай отдельный Overview для каждого семейства.

## Матрица

- State — основные колонки.
- Device — подколонки внутри State.
- Style или Type — группы строк.
- Size — строки внутри группы.
- Boolean и structural properties выноси в подгруппы или отдельный Overview, если таблица становится нечитаемой.

Неподдерживаемые сочетания оставляй пустыми. Не подменяй их похожим инстансом.

## Создание

- Эталон принципа: Button / Overview `34198:23721` в Lib-iOS.
- Создавай связанные instances, не detach.
- Не меняй исходный component set, variants, свойства, размеры и токены.
- Используй существующее оформление библиотеки и вложенный auto layout.
- Именуй результат `Overview · <Component>` или по конвенции страницы.
- Не перезаписывай вручную собранный Overview без явного разрешения; создай generated draft рядом.

## Проверка

Проверь количество variants и instances, связи с main components, соответствие подписей properties, пустые комбинации, клиппинг и визуальную читаемость. Верни nodeId Overview, количество variants, instances, дублей и пропусков.
