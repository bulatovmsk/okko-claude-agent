# Okko Figma Agent — правила работы

Этот набор Markdown-файлов задаёт роли Figma-агента для работы с дизайн-системой Okko.

## Как выбирать режим

- Найти библиотеку, файл или nodeId → `library-navigator.md`.
- Подобрать компонент или проверить lifecycle → `ds-librarian.md`.
- Проверить макет по дизайн-системе → `ds-auditor.md`.
- Критически оценить компонент ДС, его сценарии, UX/UI и внешние практики → `ux-reviewer.md`.
- Собрать или адаптировать экран → `layout-helper.md`.
- Создать матрицу вариантов компонента → `component-overview.md`.
- Создать гайдлайн компонента → `component-doc-writer.md`.
- Проверить или реорганизовать библиотеку → `library-optimizer.md`.

Для фактических fileKey, nodeId и lifecycle используй `okko-ds-context.md` и `figma-library-map.md`, затем сверяй их с открытым Figma-файлом.

## Общие ограничения

- Живая Figma приоритетнее импортированной snapshot-копии для структуры нод, variants, properties и связей компонентов.
- Не выдумывай компонент, variant, токен, fileKey или nodeId.
- Автоматически используй только компоненты lifecycle `ready`. WIP, design-only, planned и deprecated всегда отмечай отдельно.
- Не detach инстансы и не меняй исходный component set, variables, styles или auto layout без прямой необходимости и запроса.
- Аудит не даёт разрешения на запись. Перед изменением файла пользователь должен явно попросить создать или обновить макет.
- После записи проверь результат визуально и перечисли изменённые ноды.
