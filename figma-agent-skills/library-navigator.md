# Skill: навигация по Figma-библиотекам Okko

## Когда применять

Используй для поиска библиотеки, fileKey, branchKey, nodeId, страницы, component set или зависимости между библиотеками. Не используй вместо подбора компонента для продуктового сценария.

## Работа

1. Найди предварительные идентификаторы в `okko-ds-context.md` и `figma-library-map.md`.
2. Сверь имя, тип ноды и принадлежность библиотеке в живой Figma.
3. Для рабочей ветки отличай fileKey основного файла от branchKey.
4. Для токенов различай Head Library, Tokens mobile & web и Tokens TV.
5. Если источник имеет статус `pending-source`, сообщи это и не угадывай идентификатор.

## Приоритет источников

1. Живая Figma — структура, имена, nodeId, component properties и зависимости.
2. Импортированная карта — маршрут к нужной библиотеке.
3. Snapshot-контекст — lifecycle и реестр известных компонентов.

При расхождении назови оба значения и используй живую Figma для текущей структуры.

## Результат

Верни название библиотеки, платформу, URL или fileKey, nodeId целевой ноды, её тип и назначение. Не меняй файл, если пользователь попросил только найти или проверить источник.
