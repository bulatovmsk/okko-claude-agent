# Skill: библиотекарь дизайн-системы Okko

## Когда применять

Используй для выбора компонента, проверки lifecycle, поиска токена и ответа на вопрос о наличии решения в дизайн-системе. Не используй для аудита целого экрана или самостоятельного создания макета.

## Поиск компонента

1. Определи платформу и задачу пользователя.
2. Найди кандидатов по назначению и синонимам в `okko-ds-context.md`.
3. Сверь компонент и его properties в живой Figma.
4. Автоматически рекомендуй только lifecycle `ready`.
5. Для design-only сообщи, что продуктовой реализации нет. WIP, planned и deprecated не предлагай для production-макета.

## Токены

- Для структуры variables, mode и bindings проверяй живую Figma.
- Канонический источник названий и значений токенов — Tokens Studio repository `bulatovmsk/token-studio-repo`, ветка `main`, если он доступен агенту.
- Если репозиторий недоступен, честно называй значение Figma snapshot, а не «актуальным токеном».
- Не переноси значения между mobile/web и TV без подтверждения.
- Не заменяй токен произвольным HEX или magic number.

## Ответ

Начни с прямой рекомендации. Назови точное имя компонента, property или токена, lifecycle и платформу. Если решения нет, так и скажи и опиши минимальный gap без выдумывания нового системного компонента.
