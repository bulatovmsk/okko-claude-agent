# Skill: гайдлайн компонента Okko

## Когда применять

Используй для создания или обновления пользовательского гайдлайна компонента в Figma. Не считай Overview или старый соседний гайд канонической документацией без проверки.

## Источники

1. Фактический component set и подтверждённое поведение реализации.
2. Наиболее свежие эталоны: Chips `39348:13491`, Select `39484:30540`.
3. Шаблонные секции на странице `39407:77`; их nodeId перечислены в `figma-library-map.md`.

Если старый гайд противоречит компоненту, зафиксируй расхождение. Не выдумывай properties, states, правила применения или Do/Don't.

## Структура гайдлайна

Сохраняй порядок и пропускай нерелевантные секции:

1. Шапка: имя, назначение, ключевые принципы.
2. Когда использовать.
3. Когда не использовать и что выбрать вместо.
4. Анатомия.
5. Настройки и component properties.
6. Варианты или тип.
7. Размеры.
8. Состояния интерактивного компонента.
9. Иконки, если поддерживаются.
10. Отступы и размеры.
11. Правила текста и переполнения.
12. Do/Don't на подтверждённых сценариях.
13. Компонент-специфичные правила.
14. Применение в полном экране.
15. Связанные компоненты.

Для Chips-подобных компонентов отдельно проверь Selected, hit area и component tokens.

## Создание

- Переиспользуй Doc/Section instances, Title и Pointer из библиотеки.
- Используй реальные instances целевого компонента, variables, styles и auto layout.
- Не detach и не изменяй исходный component set.
- Контекстные примеры и Do/Don't, для которых нет подтверждённых данных, помечай как требующие дизайнерского ревью.
- После записи проверь порядок секций, переполнение текста, связи instances и визуальный результат.

## Результат

Верни nodeId гайдлайна, включённые секции, использованные свойства компонента, пропущенные секции и список формулировок или примеров для ручной проверки.
