# Дизайн-система Окко

> Это сводный локальный источник дизайн-системы для repo-scoped skills Codex.
> После обновления данные копируются в `.agents/skills/*/references/` командой `scripts/sync-skill-references.sh`.

## Обзор

Окко — стриминговый видеосервис. Дизайн-система покрывает четыре платформы:

- **Web** — основной сайт и веб-плеер
- **iOS** — нативное приложение для iPhone/iPad
- **Android** — нативное приложение для Android-смартфонов и планшетов
- **TV** — Android TV и SmartTV Web (LG/Samsung), 10-foot UI с D-pad навигацией

**Источник правды — живые Figma-библиотеки.** Их fileKey, nodeId и зависимости описаны в `.agents/skills/design-figma-libraries/references/libraries-map.md`. Локальная папка `design-system/` — синхронизированная выжимка для автономной работы skills.

## Что входит в ДС

| Раздел | Где смотреть | Кратко |
|---|---|---|
| Токены | `tokens/` | Цвета, типографика, отступы, радиусы, тени, motion |
| Компоненты | `components/` | Карточки компонентов с описанием, вариантами, ограничениями |
| Платформенные правила | `platforms/` | Web, iOS, Android, TV — что меняется на каждой платформе |
| Бренд | `brand/` | Voice, do/don't, ограничения использования логотипа |
| Библиотеки и lifecycle | `registry/` | Источники Figma, зависимости и правила доступности компонентов |
| Платформенные mappings | `mappings/` | Направленные соответствия iOS, Android и Web |
| Кейсы и gaps | `knowledge/` | Подтверждённые решения и открытые вопросы |
| Контекст агентов | `generated/` | Генерируемый индекс и Markdown-контекст |

## Как пользоваться в Codex

1. **При генерации макетов:** всегда использовать токены из `tokens/`, а не magic values. Все размеры, цвета, отступы — через токены.
2. **При выборе компонентов:** сверяться с `components/`. Если подходящего нет — спросить, а не выдумывать новый.
3. **При учёте платформы:** читать соответствующий файл из `platforms/`. Не путать Android-стиль с iOS.
4. **При сомнении:** показать варианты пользователю с пометкой, где сделан выбор.
5. **При выборе lifecycle:** автоматически использовать только `ready`; остальные статусы объяснять явно.

## Запрещено

- Цвета вне палитры (`tokens/colors.md`).
- Шрифты вне типографической системы (`tokens/typography.md`).
- Самописные компоненты, когда есть подходящий из библиотеки.
- Иконки вне `components/icons.md` — иначе спросить.
- Жёстко зашитые размеры (24px, 16px, 8px и т.п.) — только через токены spacing.

## Связь с Figma

Карта live-библиотек и документации: `.agents/skills/design-figma-libraries/references/libraries-map.md`.

При расхождении этого документа и Figma — **Figma приоритетнее**. Этот документ обновляется через `scripts/sync-from-figma.sh`.

Машиночитаемые источники компонентов хранятся в `components/figma-sources.json`.
Для каждой основной карточки там фиксируются `fileKey`, `branchKey`, API key и
нормализованный `nodeId`; гайды и продуктовые примеры записываются как связанные
источники. Регистрация и повторная проверка выполняются через
`scripts/figma_components.py`, который изменяет только управляемый Figma-блок
карточки и сохраняет ручное описание.
