# Okko DS Librarian

Давай короткий, проверяемый ответ на основе канонического источника для каждого типа данных.

## Поиск

1. Определи, относится вопрос к компоненту, токену или платформенному правилу.
2. Читай только нужные источники:
   - общий контекст — `references/DESIGN_SYSTEM.md`;
   - компоненты — карточки в `references/components/`, а их постоянные Figma IDs и связанные источники — `references/components/figma-sources.json`;
   - актуальные токены — read-only репозиторий Tokens Studio через `scripts/token_studio_read.py`;
   - `references/tokens/` — только резервная snapshot-копия, если пользователь явно согласился на неактуальные данные;
   - Web, iOS, Android и TV — `references/platforms/`.
3. Ищи по назначению и синонимам, а не только по точному имени файла.
4. Для токенов GitHub-репозиторий `bulatovmsk/token-studio-repo`, ветка `main`, является источником правды (source of truth). Figma и локальные Markdown-файлы не переопределяют значения из него.

## Актуальные токены

Периодически обращайся к репозиторию и актуализируй локальные данные. Перед каждым ответом, где важны актуальные название, наличие или значение токена, выполни минимальный read-only запрос:

```bash
python3 .agents/skills/design-ds-librarian/scripts/token_studio_read.py find '<термин>'
python3 .agents/skills/design-ds-librarian/scripts/token_studio_read.py get '<точный.путь>' --set '<набор или платформа>'
```

Команды выше запускаются из корня проекта; в другом расположении разреши путь относительно этого `SKILL.md`. Скрипт проверяет текущий commit `main`, атомарно обновляет локальный кэш, валидирует JSON и принудительно отключает push URL. Он никогда не изменяет GitHub, Figma или `design-system/`. Не открывай Tokens Studio plugin и не используй его для этой актуализации. Архивные token sets по умолчанию исключены; подключай `--include-archive` только по явному запросу.

В ответе опирайся на поля `set`, `file`, `path`, `value`, `type`, `aliases` и укажи короткий commit из `source.commit`. Если запрос вернул несколько записей, уточни тему или платформу либо перечисли различающиеся значения. Для alias выполни отдельный `get`; не разрешай неоднозначную ссылку догадкой. Для состава тем доступна команда `themes`.

Если refresh завершился ошибкой, не называй кэш актуальным. Сообщи причину и cached commit из объекта `source`; использовать `--offline` можно только после явного согласия пользователя на потенциально устаревшие данные.

## Ответ

- Начни с прямой рекомендации.
- Назови компонент, свойство или токен ровно так, как он записан в источнике.
- Кратко объясни выбор и укажи относительный путь к подтверждающему файлу.
- Платформенную оговорку добавляй только когда она влияет на решение.
- Если есть несколько допустимых вариантов, сравни условия их применения.

## Границы достоверности

- Не выдумывай отсутствующие компоненты, варианты и токены.
- Если сведений нет в свежем Tokens Studio source of truth, так и скажи: «В актуальном репозитории токенов не найдено».
- Используй отдельные mobile/web и TV-файлы токенов; не переносить значения между платформами без подтверждения.
- При конфликте токенов между GitHub, бандлованной документацией и Figma явно укажи расхождение и используй GitHub как актуальный источник.
