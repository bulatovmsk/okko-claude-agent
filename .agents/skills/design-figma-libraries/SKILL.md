# Okko Figma Libraries

Используй этот skill как карту источников и безопасный маршрут обновления локальной выжимки ДС.

## Навигация

Для вопросов о библиотеках, ключах, нодах и зависимостях прочитай [libraries-map.md](references/libraries-map.md). Отвечай конкретным fileKey/nodeId и назначением источника.

Приоритет источников для Figma-структуры, fileKey, nodeId и библиотечных зависимостей:

1. живая Figma;
2. локальный `design-system/`;
3. статическая карта библиотек.

Если источники расходятся, укажи это явно.

Для названий, наличия и значений дизайн-токенов этот порядок не применяется: source of truth — read-only `bulatovmsk/token-studio-repo/main`. Используй маршрут `design-ds-librarian`; не выдавай Figma Variables или Markdown snapshot за более свежий источник токенов.

## Получение данных

- Для массовых read-only запросов используй REST-скрипты проекта: `scripts/figma-api.sh`, `scripts/figma-fetch-node.sh`, `scripts/figma-render.sh`.
- Для интерактивного чтения или записи используй доступные Figma-инструменты. Перед каждым вызовом загружай обязательный prerequisite skill текущей среды; перед `use_figma` обязателен Figma-use workflow.
- Не показывай и не записывай значение `FIGMA_TOKEN` в вывод.

## Компоненты по ссылкам

Если пользователь присылает ссылки на компоненты для постоянного запоминания
или просит актуализировать сохранённый компонент, полностью прочитай
[`component-workflow.md`](references/component-workflow.md) и используй
`scripts/figma_components.py`. Постоянные идентификаторы хранятся в
`design-system/components/figma-sources.json`, а не только в контексте диалога.

Основную карточку связывай с `COMPONENT` или `COMPONENT_SET`. Если ссылка ведёт
на страницу или секцию с семейством однотипных компонентов, регистрируй её как
`collection` и сохраняй nodeId всех найденных членов в одной групповой карточке.
Ноды гайда и продуктовых примеров регистрируй как связанные источники; они не
должны подменять компонент или коллекцию. Автоматически обновляй только блок
`FIGMA_SYNC` и сохраняй ручные разделы карточки.

## Синхронизация

Запускай синхронизацию только по явному запросу пользователя. Перед изменениями прочитай [sync-workflows.md](references/sync-workflows.md), выбери минимальный target и выполни соответствующий скрипт из корня проекта.

Синхронизация из Figma не используется для ответа на вопросы о текущих токенах и не должна перезаписывать канонические Tokens Studio JSON. Read-only запрос к GitHub не является Figma-синхронизацией.

Для полного workflow используй `scripts/sync-from-figma.sh`: он работает через staged-копию и публикует изменения только после разрешения aliases, пересборки references и валидации skills. Если Variables REST API недоступен, сначала получи минимальный variable dump через Figma MCP по маршруту из [sync-workflows.md](references/sync-workflows.md) и передай его через `--variables-dir`.

После обновления:

1. убедись, что отчёт имеет статус `Завершено`;
2. проверь run-specific diff из отчёта;
3. перечисли обновлённые данные или точную причину блокировки.

Не коммить и не отправляй изменения без отдельного запроса.

## Ограничения

- REST Variables API может быть недоступен без Enterprise scope; не повторяй заведомо запрещённый запрос.
- Не выдумывай fileKey, nodeId, модель TV или поддержку движка.
- Если из-за лимита инструмента всё же понадобился временный Figma-узел, не удаляй его до сохранения dump; после успешного переноса удали только созданный тобой узел.
