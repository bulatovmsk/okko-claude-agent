# Okko Figma Libraries

Используй этот skill как карту источников и безопасный маршрут обновления локальной выжимки ДС.

## Навигация

Для состава библиотек, их статуса и графа зависимостей сначала прочитай машинный реестр [`libraries.json`](references/registry/libraries.json). Для ключевых нод и подробной навигации затем используй [libraries-map.md](references/libraries-map.md). `pending-source` означает, что fileKey ещё не подтверждён: не пытайся угадать его. Отвечай конкретным fileKey/nodeId и назначением источника.

Приоритет источников для Figma-структуры, fileKey, nodeId и библиотечных зависимостей:

1. живая Figma;
2. локальный `design-system/`;
3. статическая карта библиотек.

Если источники расходятся, укажи это явно.

### После слияния ветки в мастер

- Ссылка пользователя на мастер становится рабочим источником для продолжения задачи. Заново проверь имена, nodeId и main component зависимостей; не продолжай запись в прежнюю ветку из памяти.
- При переносе ссылок проверь наличие целевого nodeId в мастер-файле. Обновляй не только ссылку на набор, но и навигацию, связи гайда и паспорта, fade и другие зависимости в разрешённой области работы.
- Удаление V2 или другого суффикса не доказывает новый компонент или новую реализацию. Сверяй идентичность по структуре и связям. Цветной маркер без подтверждённой легенды не устанавливает lifecycle.
- Если пользователь просит только поправить документацию, это не запрос на массовую синхронизацию локального реестра или переименование компонентов. Для редакторского workflow используй `design-doc-writer`.

Для названий, наличия и значений дизайн-токенов этот порядок не применяется: source of truth — read-only `bulatovmsk/token-studio-repo/main`. Используй маршрут `design-ds-librarian`; не выдавай Figma Variables или Markdown snapshot за более свежий источник токенов.

## Оформление компонента и документации

При создании или обновлении оформления комплекта читай [общий эталон](../design-doc-writer/references/component-presentation.md): компонент слева, гайд по центру, паспорт справа, общая секция без имени. При переносе сохраняй эту компоновку и пустое имя секции. Запрос на обучение оформлению не требует регистрации эталонной секции как компонента или массовой синхронизации.

Для hover web-контролов читай [соответствие эффекта основной заливке](references/control-hover.md): Glassy требует Glassy Hover, Solid — Solid Hover; Selected использует Solid Inverse.

## Получение данных

- Для массовых read-only запросов используй REST-скрипты проекта: `scripts/figma-api.sh`, `scripts/figma-fetch-node.sh`, `scripts/figma-render.sh`.
- Для интерактивного чтения или записи используй доступные Figma-инструменты. Перед каждым вызовом загружай обязательный prerequisite skill текущей среды; перед `use_figma` обязателен Figma-use workflow.
- Не показывай и не записывай значение `FIGMA_TOKEN` в вывод.

Для продолжения адаптации Chips Web читай [контекст Chips Web](references/chips-web.md): текущий мастер, документация, свойства и согласованные привязки.

Для Select Web читай [контекст Select Web](references/select-web.md): текущий мастер, размеры Default/Small/Large, компонентные токены левой иконки, правая зона, гайд, паспорт и Overview.

## Компоненты по ссылкам

Если пользователь просит сравнить платформенные версии и перенести изменения в компонент, прочитай [component-parity.md](references/component-parity.md). Этот маршрут изменяет указанный компонент в Figma; регистрация источников и обновление локального каталога — отдельные операции. Запрос «сравни и поправь Android по iOS» уже разрешает необходимые изменения Android-компонента.

Если пользователь присылает ссылки на компоненты для постоянного запоминания
или просит актуализировать сохранённый компонент, полностью прочитай
[`component-workflow.md`](references/component-workflow.md) и используй
`scripts/figma_components.py`. Постоянные идентификаторы хранятся в
`design-system/components/figma-sources.json`, а не только в контексте диалога.
При регистрации основной ноды указывай `--platform` и `--library-id`, если это
не iOS/`lib-ios`. Допустимые library ID бери только из машинного реестра.

Основную карточку связывай с `COMPONENT` или `COMPONENT_SET`. Если ссылка ведёт
на страницу или секцию с семейством однотипных компонентов, регистрируй её как
`collection` и сохраняй nodeId всех найденных членов в одной групповой карточке.
Ноды гайда и продуктовых примеров регистрируй как связанные источники; они не
должны подменять компонент или коллекцию. Автоматически обновляй только блок
`FIGMA_SYNC` и сохраняй ручные разделы карточки.

Для `Lib-iOS` текущая база обучения ограничена основными публичными
компонентами, которые пользователь прислал и подтвердил в этом репозитории.
Не обходи оставшиеся страницы библиотеки с целью расширить базу автоматически.
Продуктовые компоненты и компоненты, живущие только в дизайне (`design-only`),
пока не регистрируй ни как основные карточки, ни как связанные источники. Их
можно читать только как контекст или зависимость уже зарегистрированного
основного компонента. Добавлять их в базу можно лишь после нового явного
указания пользователя.

## Синхронизация

Запускай синхронизацию только по явному запросу пользователя. Перед изменениями прочитай [sync-workflows.md](references/sync-workflows.md), выбери минимальный target и выполни соответствующий скрипт из корня проекта.

Синхронизация из Figma не используется для ответа на вопросы о текущих токенах и не должна перезаписывать канонические Tokens Studio JSON. Read-only запрос к GitHub не является Figma-синхронизацией.

Для полного workflow используй `scripts/sync-from-figma.sh`: он работает через staged-копию и публикует изменения только после разрешения aliases, пересборки references и валидации skills. Если Variables REST API недоступен, сначала получи минимальный variable dump через Figma MCP по маршруту из [sync-workflows.md](references/sync-workflows.md) и передай его через `--variables-dir`.

После обновления:

1. убедись, что отчёт имеет статус `Завершено`;
2. проверь run-specific diff из отчёта;
3. перечисли обновлённые данные или точную причину блокировки.

Не коммить и не отправляй изменения без отдельного запроса.

## Ограничения

- REST Variables API может быть недоступен без Enterprise scope; не повторяй заведомо запрещённый запрос.
- Не выдумывай fileKey, nodeId, модель TV или поддержку движка.
- Если из-за лимита инструмента всё же понадобился временный Figma-узел, не удаляй его до сохранения dump; после успешного переноса удали только созданный тобой узел.
