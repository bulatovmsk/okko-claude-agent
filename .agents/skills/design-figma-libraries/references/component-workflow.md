# Регистрация и актуализация компонентов по Figma-ссылкам

Постоянный реестр компонентов находится в
`design-system/components/figma-sources.json`. Это источник для поиска
`fileKey`, `branchKey`, `apiFileKey`, `nodeId`, карточки и связанных Figma-нод.
Сырые ответы Figma не коммитятся и могут храниться только в `.figma-cache/`.

## Новая ссылка

1. Сначала нормализуй и проверь ссылку без записи:

   ```bash
   python3 scripts/figma_components.py parse '<figma-url>'
   ```

2. Для основной ноды `COMPONENT` или `COMPONENT_SET` зарегистрируй компонент:

   ```bash
   python3 scripts/figma_components.py register '<figma-url>'
   ```

   Имя берётся из живой ноды. `--slug` и `--name` нужны только для осознанного
   переопределения. Команда создаёт или обновляет карточку, реестр и
   сгенерированный блок карты библиотек, затем пересобирает references и
   валидирует навыки.

   Если тот же slug уже зарегистрирован на ветке, явный `--slug` позволяет
   перевести источник на присланную main-ссылку без создания дубликата. Делай
   это только когда пользователь дал актуальную ссылку на тот же компонент.

   После автоматической регистрации изучи ноду и доступный контекст применения:
   заполни ручные разделы «Назначение», «Когда использовать», платформенные
   особенности и связи только подтверждёнными сведениями. Не оставляй TODO в
   готовой рабочей карточке и не выводи продуктовые правила из одного имени слоя.

3. Если REST-доступ недоступен, получи read-only JSON ноды через Figma MCP и
   передай его без изменения Figma:

   ```bash
   python3 scripts/figma_components.py register '<figma-url>' \
     --payload .figma-cache/component-node.json
   ```

4. Гайд или продуктовый пример не регистрируй как основной компонент. Свяжи
   его с уже существующей карточкой:

   ```bash
   python3 scripts/figma_components.py register '<figma-url>' \
     --kind guide --component chips
   python3 scripts/figma_components.py register '<figma-url>' \
     --kind product --component chips
   ```

5. Если ссылка ведёт на страницу или секцию, внутри которой находится семейство
   однотипных `COMPONENT`/`COMPONENT_SET`, зарегистрируй одну коллекцию. В карточке
   сохранятся имена, размеры, свойства и nodeId всех членов:

   ```bash
   python3 scripts/figma_components.py register '<figma-url>' \
     --kind collection --slug layouts-ios
   ```

   Используй collection только для реального семейства сборочных пресетов или
   связанных компонентов. Обычный гайд или продуктовый экран остаётся связанным
   источником.

## Актуализация

Обновить один компонент по slug или по сохранённой ссылке:

```bash
python3 scripts/figma_components.py refresh chips
python3 scripts/figma_components.py refresh '<figma-url>'
```

Без target команда проверяет все основные компоненты. Для предварительного
сравнения без записи используй `--dry-run`. В JSON-отчёте поле `changes`
показывает точные переименования, добавленные и удалённые properties, значения
вариантов и зависимости; для размеров указывается факт структурного изменения.
Пустой список означает, что структура не изменилась.

Скрипт перезаписывает только блок между `FIGMA_SYNC`-маркерами. Назначение,
правила применения, accessibility и другие ручные разделы карточки сохраняются.
Переименование ноды отражается в снимке и отчёте, но устойчивый slug и имя
карточки автоматически не меняются.

После refresh сравни живой снимок с ручными разделами карточки. Если назначение,
статус или правила расходятся, зафиксируй конфликт в отчёте пользователю и не
переписывай продуктовую трактовку молча.

## Проверка без Figma

```bash
python3 scripts/figma_components.py validate
bash scripts/sync-skill-references.sh
bash scripts/validate-skills.sh
```

Проверка подтверждает уникальность slug и Figma-источников, нормализованные
nodeId, наличие карточек и разрешимость локальных Markdown-ссылок.

## Границы

- Для URL ветки `branchKey` сохраняется отдельно и используется как
  `apiFileKey`; исходный `fileKey` не теряется.
- Основная карточка принимает `COMPONENT`/`COMPONENT_SET`; страница или секция с
  семейством компонентов принимается как `collection`.
- Значения и наличие токенов не извлекаются этим workflow. Для них source of
  truth — read-only `bulatovmsk/token-studio-repo/main` через
  `design-ds-librarian`.
- Не выводи `FIGMA_TOKEN`; REST-wrapper читает его только из `.env`.
