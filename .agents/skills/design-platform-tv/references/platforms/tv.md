# TV — платформенные правила

Контекст: Android TV и SmartTV Web (LG webOS, Samsung Tizen). 10-foot UI: пользователь смотрит на экран с 2–4 метров, управление D-pad или ИК-пультом.

## Ключевое отличие от других платформ

- **Нет указателя, нет тача** — только D-pad и кнопки (OK, Back, Menu, Play/Pause).
- **Фокус — главное.** В любой момент один и только один элемент в фокусе, и пользователь должен видеть его без сомнений.
- **Расстояние просмотра** — всё крупнее: текст, hit-area, отступы.

## Focus management

### Визуально

- Focus-state **обязательно отличается** от не-focus: scale-up (обычно 1.05–1.1×), обводка, тень или их комбинация
- Focus-state **никогда не путать с hover** — TV не имеет hover
- Анимация перехода фокуса: 100–200ms ease-out
- На low-end профиле, где анимации отключены, Focus переключается мгновенно, но сохраняет все статические визуальные признаки.

### Логически

- Соседние focusable элементы должны быть на одной линии (горизонтальной или вертикальной)
- D-pad движение между соседними элементами без пропусков
- Возврат фокуса при возврате на экран — на последний сфокусированный элемент
- Trap focus в модалках обязателен

## Hit-area (для focus, не для тача)

- Минимальный размер фокусируемого элемента: 80×80px при 1080p
- Между focusable элементами — пробел не менее 16px

## Состояния

- Default (не в фокусе)
- Focused (обязательно визуально выделено)
- Pressed (короткое — при нажатии OK)
- Disabled (visible но not focusable)
- Selected (для табов, чекбоксов и пр.)

### Fallback-состояния кнопок на low-end TV

Использовать, когда платформа или runtime-профиль телевизора отключает анимации из-за производительности. Состояния не должны зависеть от движения: пользователь должен различать фокус, подтверждение нажатия, загрузку и ход автопереключения по одному статичному кадру.

#### Button

| Состояние | Статический fallback |
|---|---|
| `Rest` | Базовый вид кнопки без дополнительной индикации. |
| `Focus` | Штатная контрастная обводка и/или фон фокуса; переход без анимации. |
| `Pressed · TVxx` | Внутренняя кнопка уменьшается до 95% и получает чёрный state-layer 12%. Контейнер сохраняет исходный размер и центрирует кнопку, поэтому layout не меняется. |
| `Pressed · Android TV` | Размер не меняется; поверх фона используется чёрный state-layer 12%. |
| `Loading` | Иконка заменяется на статичный `Objects / Hourglass_Bold`. UX не должен зависеть от движения loading-полосы или спиннера. |
| `Progress` | Сохраняется явный текстовый отсчёт. Допустимы `Icon + Text` и `Text`; вариант только с иконкой не используется, потому что скрывает значение прогресса. |

#### Toggle Button

- Поддерживаются `Rest`, `Focus`, `Pressed · TVxx`, `Pressed · Android TV` и `Loading` для `Selected=False/True`.
- Правила `Pressed` и `Loading` совпадают с Button; статичный hourglass должен оставаться контрастным на выбранной светлой кнопке.
- `Progress` не используется: у Toggle Button нет сценария текстового таймера или отсчёта.
- Доступны штатные конфигурации `Icon + Text`, `Text` и `Icon`.

#### Поведение прототипа и продукта

- Цепочка TVxx: `Rest → Focus → Pressed → Loading → Rest`.
- Все визуальные переходы мгновенные: без Smart Animate, easing и интерполяции. Пауза 0,8 секунды в демонстрационном прототипе — длительность показа `Loading`, а не анимация перехода.
- У Toggle Button после `Loading` меняется `Selected`; у обычного Button состояние возвращается в исходный `Rest`.
- `Progress` у Button выбирается отдельно или управляется продуктовой логикой.
- Не переносить hover-триггер из Figma-прототипа в продуктовую TV-логику: на устройстве состояния запускаются D-pad-фокусом и кнопкой OK.
- Перед релизом проверять читаемость fallback-состояний на целевых low-end моделях и с реального расстояния просмотра.

## Что НЕ работает на TV

- Hover — нет указателя
- Touch gestures — нет таскрина
- Right-click контекстные меню — заменяются на Menu-кнопку пульта
- Hamburger menu — плохо для D-pad, использовать боковую панель
- Маленькие иконки без поясняющего текста — плохо различимы с 3 метров

## Перформанс на SmartTV Web

- Старые модели LG/Samsung — слабое железо, ограниченная GPU
- Избегать: больших размытий, тяжёлых градиентов, одновременных анимаций
- Использовать CSS transform/opacity (GPU-accelerated), не left/top/width
