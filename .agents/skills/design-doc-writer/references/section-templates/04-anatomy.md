# Секция 4 — Анатомия компонента

## Что включает

1. **Заголовок** — «Анатомия компонента»
2. **Изолированная иллюстрация** — компонент крупно, без окружающего контекста
3. **Pointer-аннотации** — стрелки от компонента к подписям:
   - Название части (например, «Контейнер», «Лейбл», «Иконка слева»)
   - В каких токенах живут свойства этой части (например, `radius.button.m`, `color.text.on-accent`)

## Пример заполнения (Button, Primary, размер Default)

Иллюстрация: кнопка `Primary / Default` крупно, по центру.

Pointer-аннотации (по часовой):
- ↗ **Контейнер** — `color.bg.button.primary`, `radius.button.m`, `spacing.button.h`
- ↘ **Иконка** (опционально) — `size.icon.button`, `color.icon.on-accent`
- ↘ **Лейбл** — `type.button.m`, `color.text.on-accent`
- ↙ **Hit-area** — невидимая расширенная зона минимум 44pt × 44pt
- ↖ **Внутренний отступ** — `spacing.button.v` (вертикальный), `spacing.button.h` (горизонтальный)

## Источники для авто-заполнения

- **Компонент** — берётся главный variant (часто `Primary` для кнопок, `Default` для остального)
- **Названия частей** — Skill читает структуру компонента из Figma JSON (имена слоёв)
- **Токены** — Skill ищет, какие variables привязаны к свойствам этих слоёв, и подставляет имена токенов

## Что НЕ делать

- ❌ Не аннотировать все возможные слои — только 4–7 ключевых
- ❌ Не использовать magic-значения вместо токенов (`16px` вместо `spacing.button.h`)
- ❌ Не показывать состояния, варианты или размеры — для них есть свои секции
