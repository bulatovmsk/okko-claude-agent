# Секция 4 — Анатомия компонента

## Что включает

1. **Заголовок** — «Анатомия компонента»
2. **Текстовая анатомия** — названия, назначение частей и условия их появления. Существующий текст сохраняем.
3. **Изолированная иллюстрация** — связанный инстанс компонента крупно, без окружающего контекста
4. **Фиолетовые нумерованные Pointer-аннотации и легенда** — конец выноски точно указывает на часть:
   - Название части (например, «Контейнер», «Лейбл», «Иконка слева»)
   - При необходимости — фактически используемые токены; подробности вложенных компонентов заменяем ссылками на их документацию.

## Пример заполнения (Button, Primary, размер Default)

Иллюстрация: кнопка `Primary / Default` крупно, по центру.

Pointer-аннотации (по часовой):
- ↗ **Контейнер** — `color.bg.button.primary`, `radius.button.m`, `spacing.button.h`
- ↘ **Иконка** (опционально) — `size.icon.button`, `color.icon.on-accent`
- ↘ **Лейбл** — `type.button.m`, `color.text.on-accent`
- ↙ **Hit-area** — невидимая расширенная зона минимум 44pt × 44pt
- ↖ **Внутренний отступ** — `spacing.button.v` (вертикальный), `spacing.button.h` (горизонтальный)

## Источники для авто-заполнения

- **Компонент** — выбирается демонстрационный инстанс, на котором видны объясняемые части. Проверяются также скрытые слои и публичные переключатели.
- **Названия частей** — Skill читает структуру компонента из Figma JSON (имена слоёв)
- **Токены** — Skill ищет, какие variables привязаны к свойствам этих слоёв, и подставляет имена токенов

## Что НЕ делать

- ❌ Не перечислять декоративные технические слои, но и не пропускать значимые части ради ограничения количества выносок.
- ❌ Не использовать magic-значения вместо токенов (`16px` вместо `spacing.button.h`)
- ❌ Не превращать анатомию в матрицу состояний. Условно видимую часть можно показать в подходящем состоянии с подписью условия: например, верхний и нижний Trim при промежуточной позиции прокрутки. Trim и полоса прокрутки — разные части.
