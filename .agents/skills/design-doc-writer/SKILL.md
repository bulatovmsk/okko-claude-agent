# Okko Component Doc Writer

Готовь гайдлайн компонента по каркасу ДС и, когда доступна запись, собирай его в указанном Figma-файле.

## Источники

1. Всегда прочитай `references/STRUCTURE.md`.
2. Определи нужные секции по свойствам и назначению компонента.
3. Читай только шаблоны выбранных секций из `references/section-templates/`. В текущем комплекте детальные шаблоны есть не для всех секций; отсутствие шаблона не заменяй выдуманным эталоном.

## Исследование компонента

- Используй Figma-ссылку пользователя как основной источник структуры, variants, component properties, размеров и состояний.
- Перед любым Figma-вызовом загружай обязательный prerequisite skill текущей среды; перед `use_figma` обязателен Figma-use workflow.
- Если Figma недоступна, работай по предоставленным данным и ясно отметь границы достоверности.
- Не добавляй свойства и варианты, которых нет у компонента.

## Состав гайдлайна

Сохраняй порядок из `STRUCTURE.md`.

- Обязательные секции включай всегда, кроме условных, которые не относятся к компоненту.
- Варианты, размеры, состояния, иконки и текст включай только при наличии соответствующего свойства или поведения.
- Компонент-специфичные секции добавляй, когда без них нельзя объяснить важное правило.
- Do/Don't основывай на подтверждённых сценариях; спорные примеры помечай для проверки дизайнером.

## Создание в Figma

Если пользователь попросил создать или обновить гайдлайн и дал целевой файл:

1. Сохрани variables, styles, компоненты и auto-layout существующей библиотеки.
2. Переиспользуй доступные шаблонные секции и существующие инстансы вместо ручной имитации.
3. Заполни тексты, анатомию, properties, состояния и контекстные примеры данными целевого компонента.
4. Не отсоединяй инстансы и не меняй исходный компонент без необходимости.
5. После записи проверь структуру и визуальный результат доступными средствами.

Если записи нет, выдай полный план гайдлайна и черновики текстов, не утверждая, что Figma-фрейм создан.

## Результат

Сообщи:

- где находится созданный или обновлённый фрейм;
- какие секции включены и почему;
- что заполнено из данных компонента;
- какие формулировки и Do/Don't требуют ручной проверки;
- какие данные отсутствовали.
