# Общие правила Rail

Приняты в работе с библиотекой UI Type 11–13 ноября 2026; сохранены 16 ноября. Последние явные решения пользователя имеют приоритет над старыми источниками. Снимки геометрии проверяй в живой Figma перед изменением.

## Архитектура и источники

Агент выполняет основную сборку и проверку; дизайнер донастраивает результат и принимает окончательные визуальные решения. Рекомендательные шкалы помогают первоначальному выбору и не отменяют явную настройку дизайнера. Сохраняй такие настройки при пересборке, используя существующие компоненты и токены.

Rail — композиция из шапки, карусели и карточек, иногда фона, спонсорских или других блоков. Rail Card — повторяемая карточка, не весь UI Type.

Рабочая библиотека: [UI Type Web & Mobile](https://www.figma.com/design/TGfdPRzrhCA6CbiHsRjBSD?node-id=0-1).

- Rail Card iOS, Android и Web находятся локально на странице Rail Shared этой библиотеки. Используй экземпляр соответствующей платформы как шаблон собственной карточки UI Type; внешняя оболочка отсоединяется, вложенные платформенные базы сохраняют связи.
- Rail Heading — один общий компонент в UI Type. Phone и Tablet общие для платформ. При проверке Rail Heading переключи `Show arrow` на связанном экземпляре на ширине целевого устройства. Заголовок остаётся у левого края в обоих состояниях, видимая стрелка Base Phone/Tablet — у правого. В Base Tablet используй `Content = Fill container` и `Title = Hug contents`: при скрытой стрелке контейнер с `Space between` и `Content = Hug contents` центрирует заголовок. Desktop уже добавлен: увеличены типографика/изображения, правая стрелка шапки скрыта.
- Label, Rich Label, кнопки и другие базовые элементы остаются экземплярами Lib-iOS, Lib-Android-Mobile, Lib-Web или подтверждённой общей базовой библиотеки.
- Уникальные детали конкретного типа хранятся локально рядом с Rail. Сначала ищи подходящие существующие подписи, оверлеи, прогресс и другие запчасти. Для совместимых запчастей разница только в ширине не требует нового мастера. Рабочая карточка UI Type при этом получает варианты размеров для независимого редактирования.
- Поддерживаемое состояние Skeleton берётся из Rail Card; отдельный дубликат скелетона не создаётся.
- Исходные Rail в платформенных библиотеках используются для чтения. Их перенос не разрешает правку или удаление исходников. Ранее отдельно разрешённое удаление старых мастеров карточки не распространяется на исходные Rail.

## Три способа собрать карточку

| Способ | Применение |
|---|---|
| Rail Card со стандартным Shape | Нужны стандартные структура и пропорции |
| Rail Card, Shape=Custom | Подходит структура, нужны свободные пропорции |
| Полностью кастомная карточка | Нужны другая структура или поведение |

Стандартные пропорции обложек: Horizontal 16:9, Vertical 2:3, Square и Circle 1:1. Высота подписи и её интервалы считаются отдельно. У Custom общая высота экземпляра включает подпись, обложка занимает остаток. Нельзя считать общую высоту карточки высотой обложки.

Пользователь разрешил кастомные пропорции и собственные карточки. Прежнее временное правило «не переносить несовместимые с Rail Card пропорции» отменено. Исторические сведения об удалённых типах не заменяют живую инвентаризацию текущей ветки.

### Выбор фиксированной пропорции или Custom: порог 15%

Для нового концепта перед выбором Shape=Custom сравни пропорцию обложки с доступными фиксированными пропорциями подходящей Rail Card:

ratioConcept = ширина обложки концепта / высота обложки концепта
ratioFixed = ширина / высота фиксированной пропорции
differencePercent = abs(ratioConcept - ratioFixed) / ratioFixed × 100

Выбирай фиксированную пропорцию с минимальным differencePercent среди совместимых по структуре и форме вариантов. Если отклонение не превышает 15% (включая ровно 15%), используй её. Если от всех подходящих фиксированных пропорций отклонение больше 15%, по умолчанию используй Shape=Custom с пропорцией концепта; отдельное подтверждение только для такого выбора не требуется.

При фиксированной пропорции пересчитай высоту обложки по выбранной ширине и ratioFixed. При Custom — по ratioConcept. Подпись, шапка и отступы в измерение пропорции не входят. Не округляй отклонение до сравнения с порогом.

Например, относительно 16:9 пропорция 1,6 отклоняется на 10% — используется 16:9. Пропорция 2,1 отклоняется примерно на 18,125% от 16:9 — используется Custom, если нет другой подходящей фиксированной пропорции в пределах 15%.

Равная пропорция Square/Circle не определяет форму: сохраняй заданную дизайнером геометрию. Правило выбора пропорции не заменяет проверку структуры; при иной структуре нужна полноценная кастомная карточка. Оно не разрешает автоматически менять уже утверждённые размеры существующих Rail.

## Дефолтная картинка обложки при сборке по концепту

На каждой обложке нового UI Type по концепту всегда используй существующую дефолтную картинку-плейсхолдер библиотеки. Правило действует для всех карточек и вариантов iOS, Android и Web, включая стандартные формы, Custom и полностью кастомные карточки. Сохраняй дефолтную картинку подходящей Rail Card; для кастомной структуры переиспользуй тот же библиотечный плейсхолдер.

Не заменяй его серой заливкой из вайрфрейма, пустой обложкой или контентной картинкой из концепта. Тексты, оверлеи и исходную видимость элементов концепта переноси независимо от картинки обложки. Сохраняй технический слой Cover, пропорции, скругление, clipping и компонентные связи. Встроенный Skeleton остаётся отдельным состоянием и не заменяет плейсхолдер обычного состояния.

При проверке новой сборки проверь фактическое наличие дефолтной картинки на каждой обложке, а не только имя слоя Cover. Если дефолтный плейсхолдер не найден или недоступен, сообщи об ограничении; не генерируй и не придумывай замену. Это правило сборки по концепту не разрешает автоматически менять изображения в уже существующих UI Type при аудите.

## Токены

Радиус новых карточек выбирается по минимальной стороне скругляемого Cover после выбора пропорции: S=min(W,H). Ступени и реальные ограничения текущей библиотеки описаны в [radius.md](radius.md). Подбирается существующий токен Rail Card с сохранением темы; предлагаемая beta-шкала не меняет автоматически утверждённые радиусы и не заменяет круглую геометрию Circle.

- Между карточками: локальные rail/gap-horizontal/phone=6, tablet=8, desktop=10. На Web 1440 используется tablet=8 при Device=Desktop.
- Радиусы карточки и обложки выбираются только из системы Rail Card через rail/card/radius/*. Привязки поддерживают смену темы. Не копируй текущее число и не подставляй сторонний radius-токен. Сохраняй круглую геометрию Circle и собственные токены вложенных кнопок/лейблов.
- Внутренние padding/gap отличаются от gap карусели. Пользователь требует компонентное семейство Rail Card Padding Gap, но точный путь ещё не подтверждён. В проверенных Labels / padding были числовые 6 и 2 без привязки. До подтверждения сохраняй мастер и явно отмечай незавершённую токенизацию; не выдумывай путь и не заменяй его rail/gap-horizontal/*.
- Screen padding выбирается по платформе. Не вычитай его повторно, если родитель уже ограничил полезную область.
- Запрещено создавать новые дизайн-переменные, aliases, коллекции и токены. Разрешён импорт уже существующих переменных. При отсутствии нужной сообщи об ограничении.
- Token Studio repo — источник для чтения: bulatovmsk/token-studio-repo, main. При новых выводах о токенах проверяй актуальный commit; сохранённые значения имеют дату проверки.

## Структура

Страницы называй `<тип> Rail`, например `Vertical Rail`. Сортируй их по названию типа внутри существующих групп и сохраняй разделители. Для Grid используется формат `<тип> Grid`. Эмодзи ставь только в именах основных платформенных UI Type, включая Grid, Featured и Banner. Имена страниц, базовых компонентов и запчастей сохраняй без платформенных эмодзи. Основные компоненты `Rail <тип> 🍎 iOS`, `Rail <тип> 🤖 Android`, `Rail <тип> 🌐 Web`. Все запчасти, включая общие, публикуются в группе `x / `: `x / Rail <тип> <роль> [платформа] [размер]`. Для наполнения слотов: `x / Rail <тип> Slot <роль> [платформа] [размер]`. Не скрывай запчасти через `_`. Основные Rail, базовые Rail Card и Rail Heading остаются без `x / `. Не добавляй общий префикс UI Type и длинную иерархию через дроби.

Мастера лежат прямо на странице без SECTION и лишних контейнеров, платформы слева направо iOS → Android → Web. Запчасти рядом; общие запчасти в одном экземпляре. Проверку размещай в отдельных платформенных секциях с экранными фреймами по [device-review.md](device-review.md). Запрет секций-обёрток относится к мастерам.

На Rail Shared собраны базовые Rail Card и Heading, Rail Example, общие запчасти и примеры сеток. Rail Example — пример композиции; его экземпляр можно detach, сохранив связи вложенных базовых компонентов. Внешний экземпляр Rail Card также разрешено detach при создании собственной карточки UI Type. Heading и вложенные базовые компоненты не отсоединяй.

Внутри Rail сохраняются полезные Carousel, Row, Column и другие функциональные контейнеры. Не добавляй Base Rail и одноэлементные обёртки без роли. Техническое имя слоя Cover сохраняется для подстановки изображений.

## Перенос и проверка

Проверяй все карточки, скрытые потомки и индивидуальные overrides, включая элементы, которые визуально не видны. Встроенные возможности Rail Card не дублируй отдельными деталями. Сохраняй исходное состояние видимости. Сначала переносится действующая часть, WIP исключена.

Обложка, подпись, шапка и суммарная высота Rail измеряются раздельно. У двухрядных типов различай карточку, колонку и два ряда. N в формулах — плотность расчётной области, а не число экземпляров, создаваемых в карусели.

Шапка растягивается по доступной ширине; скрытая шапка не оставляет лишний gap. Стрелка шапки и навигация карусели — разные элементы. У Carousel `clipsContent=false`; переполнение ограничивает внешний экранный фрейм проверки. Clipping обложки сохраняется независимо.

Проверяй реальные связи с мастерами, стили и переменные, а не совпадение названий. Включай скрытые возможности на собственных временных примерах и проверяй слоты, ресайз, обрезку и текст. Удаляй только свои временные узлы. Не объявляй визуальную проверку полной инвентаризацией скрытого контента.

## Правила структуры и проверки на устройствах

Применяй [device-review.md](device-review.md). У Carousel `clipsContent=false`; переполнение ограничивает экранный фрейм проверки. Не экспонируй Heading, карточки и другие внутренние экземпляры в Nested instances конечного Rail без явного запроса. Компоненты наполнения слотов называй Rail <тип> Slot <роль> [платформа] [размер]. Общий Preview без экранных фреймов не создавай. Во время проверки не исправляй найденные ошибки автоматически и не маскируй их подбором N, изменением размеров или переопределениями проверочного экземпляра.

## Область размещения

Правила страницы `<тип> Rail` и ряда платформенных мастеров относятся к каталогизации в библиотеке. При работе в фича-файле размещай локальный Rail и проверку рядом с концептом в указанной дизайнером области. Для сеток используй доступные опубликованные стили UI Type: импорт существующего GridStyle разрешён. Если стиль недоступен, сообщи зависимость; не создавай его числовую копию и новые переменные.

## Собственная карточка вместо вложенной универсальной базы

Для новых сборок и явно запрошенной пересборки обязательно применяй [card-component.md](card-component.md): Rail Card используется как шаблон; в карусели — экземпляры собственного набора x / Rail <тип> Card <платформа> по размерам. Новая карточка не содержит универсальную Rail Card и SLOT по умолчанию, но сохраняет токены, вложенные базы и семь работающих переключателей. Это уточняет все исторические упоминания использования Rail Card/Custom и слотов в старых измерениях.
