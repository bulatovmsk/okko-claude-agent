# Общие правила Rail

Приняты в работе с библиотекой UI Type 11–13 ноября 2026; сохранены 16 ноября. Последние явные решения пользователя имеют приоритет над старыми источниками. Снимки геометрии проверяй в живой Figma перед изменением.

## Архитектура и источники

Rail — композиция из шапки, карусели и карточек, иногда фона, спонсорских или других блоков. Rail Card — повторяемая карточка, не весь UI Type.

Рабочая библиотека: [UI Type Web & Mobile](https://www.figma.com/design/TGfdPRzrhCA6CbiHsRjBSD?node-id=0-1).

- Rail Card iOS, Android и Web находятся локально на странице Rail Card этой библиотеки. Используй экземпляр соответствующей платформы.
- Rail Heading — один общий компонент в UI Type. Phone и Tablet общие для платформ. Desktop уже добавлен: увеличены типографика/изображения, правая стрелка шапки скрыта.
- Label, Rich Label, кнопки и другие базовые элементы остаются экземплярами Lib-iOS, Lib-Android-Mobile, Lib-Web или подтверждённой общей базовой библиотеки.
- Уникальные детали конкретного типа хранятся локально рядом с Rail. Сначала ищи подходящие существующие подписи, оверлеи, прогресс и другие запчасти. Разница только в ширине не требует нового мастера.
- Поддерживаемое состояние Skeleton берётся из Rail Card; отдельный дубликат скелетона не создаётся.
- Исходные Rail в платформенных библиотеках используются для чтения. Их перенос не разрешает правку или удаление исходников. Ранее отдельно разрешённое удаление старых мастеров карточки не распространяется на исходные Rail.

## Три способа собрать карточку

| Способ | Применение |
|---|---|
| Rail Card со стандартным Shape | Нужны стандартные структура и пропорции |
| Rail Card, Shape=Custom | Подходит структура, нужны свободные пропорции |
| Полностью кастомная карточка | Нужны другая структура или поведение |

Стандартные пропорции обложек: Horizontal 16:9, Vertical 2:3, Square и Circle 1:1. Высота подписи и её интервалы считаются отдельно. У Custom общая высота экземпляра включает подпись, обложка занимает остаток. Нельзя считать общую высоту карточки высотой обложки.

Пользователь разрешил кастомные пропорции и собственные карточки. Прежнее временное правило «не переносить несовместимые с Rail Card пропорции» отменено. Rail Ticket удалён пользователем; не восстанавливай его из старых отчётов.

## Токены

- Между карточками: локальные rail/gap-horizontal/phone=6, tablet=8, desktop=10. На Web 1440 используется tablet=8 при Device=Desktop.
- Радиусы карточки и обложки выбираются только из системы Rail Card через rail/card/radius/*. Привязки поддерживают смену темы. Не копируй текущее число и не подставляй сторонний radius-токен. Сохраняй круглую геометрию Circle и собственные токены вложенных кнопок/лейблов.
- Внутренние padding/gap отличаются от gap карусели. Пользователь требует компонентное семейство Rail Card Padding Gap, но точный путь ещё не подтверждён. В проверенных Labels / padding были числовые 6 и 2 без привязки. До подтверждения сохраняй мастер и явно отмечай незавершённую токенизацию; не выдумывай путь и не заменяй его rail/gap-horizontal/*.
- Screen padding выбирается по платформе. Не вычитай его повторно, если родитель уже ограничил полезную область.
- Запрещено создавать новые дизайн-переменные, aliases, коллекции и токены. Разрешён импорт уже существующих переменных. При отсутствии нужной сообщи об ограничении.
- Token Studio repo — источник для чтения: bulatovmsk/token-studio-repo, main. При новых выводах о токенах проверяй актуальный commit; сохранённые значения имеют дату проверки.

## Структура

Страница Rail <тип>; компоненты Rail <тип> iOS, Rail <тип> Android, Rail <тип> Web. Запчасти Rail <тип> <роль> [платформа] [размер]. Не добавляй общий префикс UI Type и длинную иерархию через дроби. Для будущего Grid будет свой префикс.

Мастера лежат прямо на странице без SECTION и лишних контейнеров, платформы слева направо iOS → Android → Web. Запчасти рядом; общие запчасти в одном экземпляре. Обычный FRAME допустим для примеров.

Внутри Rail сохраняются полезные Carousel, Row, Column и другие функциональные контейнеры. Не добавляй Base Rail и одноэлементные обёртки без роли. Техническое имя слоя Cover сохраняется для подстановки изображений.

## Перенос и проверка

Проверяй все карточки, скрытые потомки и индивидуальные overrides, включая элементы, которые визуально не видны. Встроенные возможности Rail Card не дублируй отдельными деталями. Сохраняй исходное состояние видимости. Сначала переносится действующая часть, WIP исключена.

Обложка, подпись, шапка и суммарная высота Rail измеряются раздельно. У двухрядных типов различай карточку, колонку и два ряда. N в формулах — плотность расчётной области, а не число экземпляров, создаваемых в карусели.

Шапка растягивается по доступной ширине; скрытая шапка не оставляет лишний gap. Стрелка шапки и навигация карусели — разные элементы. Обрезка карусели не должна случайно резать подписи, оверлеи или текст.

Проверяй реальные связи с мастерами, стили и переменные, а не совпадение названий. Включай скрытые возможности на собственных временных примерах и проверяй слоты, ресайз, обрезку и текст. Удаляй только свои временные узлы. Не объявляй визуальную проверку полной инвентаризацией скрытого контента.
