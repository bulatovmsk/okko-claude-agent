# Web: измерения Rail и правый расчётный отступ

Историческое исследование исходной Lib-Web от 11 ноября 2026. Для новой сборки действуют [текущие Web-правила](web.md) и [общие правила](common.md). Упоминания Ticket описывают старый исходник: удалённый пользователем тип в UI Type не восстанавливается.

Проверено 11 ноября 2026: [Lib-Web, UI Type Rail](https://www.figma.com/design/e72TWMOh7ibwauqgKwLnC9/Lib-Web?node-id=16685-178431), 20 верхнеуровневых наборов Rail, 120 вариантов. Измерены ширины карточек/треков, интервалы и вложенные обложки; это геометрический аудит, не полная проверка содержимого всех карточек. Сырые измерения: [web-rail-geometry.json](web-rail-geometry.json).

## Screen padding и реконструкция R

Screen padding сверены с `themes/Semantic/Numbers/WebMobile/Main.json` в `token-studio-repo/origin/main`. R ниже восстановлен по измеренным размерам распространённых семейств и ожидаемому количеству карточек; это вывод из геометрии, не найденный опубликованный Web Technical-токен.

| breakpoint | Screen padding L | Токен screen padding | Правый расчётный R для стандартных семейств | Добавка к screen padding справа | Измеренный gap |
|---|---|---|---|---|---|
| 320 | 12 | screen-padding/web/mobile | 36 | 24 | 6 |
| 375 | 12 | screen-padding/web/mobile | 36 | 24 | 6 |
| 768 | 32 | screen-padding/web/tablet | 56 | 24 | 8 |
| 1024 | 32 | screen-padding/web/tablet | 56 | 24 | 8 |
| 1440 | 56 | screen-padding/web/desktop-m | 56 | 0 | 8 |
| 1920 | 72 | screen-padding/web/desktop-l | 72 | 0 | 10 |

Не прибавляй 24 к десктопным R автоматически. В Main/Continue/Vertical/Square/Medium/Material и ряде других семейств измерения на 1440 и 1920 соответствуют обычным симметричным screen padding. Различие gap 1440=8 и 1920=10 реально присутствует; не выбирай gap только по слову desktop в названии экрана, проверь платформенную привязку.

Независимые примеры с целым N:

- Square, 375: W=160.5, N=2, G=6 → R=375−12−(2×160.5+6)=36.
- SquareSmall, 375: W=105, N=3, G=6 → R=375−12−(3×105+2×6)=36.
- Main, 1024: W=228, N=4, G=8 → R=1024−32−(4×228+3×8)=56.
- Main, 768: W≈221.33, N=3, G=8 → R≈56.
- Main, 1920: W=347.2, N=5, G=10 → R=72.
- Main, 1440: W=259.2, N=5, G=8 → R=56.

## Дробное N: отличие от iOS

Не распространяй `ceil(N)-1` из iOS JSON автоматически на Web. Измерения нескольких Web-семейств точно описываются непрерывной формулой:

```text
area = S - L - R
W = (area - (N - 1) * G) / N
# эквивалентно W = (area + G) / N - G
```

Например, при 375, L=12, R=36 и G=6:

- Vertical/Ticket: N=2.5 → W=127.2.
- Medium/Material: N=1.25 → W=260.4.
- Main/Continue/Person/Teams: N=5/3 → W=193.8.

Эти N реконструированы по геометрии и изменению ширины между 320 и 375. Не выдавай их за прочитанные из Web Technical JSON: такого набора в проверенном репозитории не найдено. Для нового концепта согласуй N и применимость непрерывной формулы, а при воспроизведении существующего типа сверяй точные размеры источника. iOS-правило пользователя и JSON с `ceil(N)-1` остаются отдельным правилом iOS.

## Исключения и расхождения

- Announces и оба Highlights имеют отдельную геометрию. Не применяй стандартные R и N без проверки. Например, Announces 375: W=306; при N=1 эффективный R=57, а не 36. Highlights 375: W=343; при N=1 эффективный R=20. Сам выбор N требует подтверждения.
- У Large 768 ширина 450, у Marketing 768 — 450.67. Вторая соответствует N=1.5 и стандартной непрерывной формуле; первая отличается примерно на 0.67 px. Не превращай эту разницу в новое общее правило отступов.
- На 1920 SquareSmall имеет ширину 213, Circle — 213.25; это небольшое расхождение/округление, а не основание вводить разные screen padding.
- У старшего варианта Marketing в имени записано 1720, но ширина компонента 1776 и карточки 585.33 совпадают с геометрией 1920. Не добавляй новый обязательный breakpoint 1720.
- Grid Layout содержит старые демонстрационные сетки, в том числе 1440 с offset 72 и gap 16. Они расходятся с актуальными Rail (ширина 1328, gap 8) и токеном desktop-m=56. Для сборки сверяй реальные Rail и текущие токены, не копируй такую сетку как актуальную автоматически.
- В Background ширина трека отличается от обычного Main из-за контейнера/фона, но ширины карточек совпадают с Main. Не выводи R только из ширины трека. У Person/Teams трек может быть шире видимой области.

## Android: только подтверждённые screen padding

`screen-padding/android/phone` = 16 px; `screen-padding/android/tablet` = 24 px. Это отдельные платформенные токены, не iOS/Web. Применяй к макетам Phone 360, Tablet Portrait 640 и Tablet Landscape 1024. После отдельного исследования Android принята сеточная модель без введения специального R: см. [Android](android.md). Значения правого отступа из старого Technical JSON не переносить автоматически.
